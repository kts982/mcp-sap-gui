# Changelog

Every release and what changed for someone running the server. The [GitHub release pages](https://github.com/kts982/mcp-sap-gui/releases) also list the merged pull requests and their authors.

## Unreleased

### Added

- **`sap_send_key` supports Shift+F11 and Shift+F12.**
  Both keys are also included in `available_keys` when
  accepted by the current SAP screen.
- **`sap_alv_cell_action`: act on a cell of an ALV grid** ([#53](https://github.com/kts982/mcp-sap-gui/pull/53)). One tool with an `action`: `click` a hotspot, `press_button` (a button in a cell), `set_checkbox`, `f4` (value help), `enter` (send the grid's changes to the application for checking; with a cell it returns that cell's value and state afterwards), `context_menu` (open the cell's menu; the response lists `menu_items` for `sap_select_alv_context_menu_item`) and `toggle_total` (open or close a subtotal's group). Until now a hotspot or a cell button could not be reached at all. A cell that is not what the action needs is refused before anything is sent (`status: rejected`): seen live, a click on a cell that is no hotspot fails with a bare "Exception occurred", a checkbox write to a cell that is no checkbox changes nothing without an error, and F4 on a cell without value help opens an information popup. The cell's row is brought on screen first, because a click or a button press on a row that is not on screen only scrolls there and the event fires on the second call. `toggle_total` needs only the row: the press is taken only in a column that carries a total, which the tool finds; on the overall total it closes every group. `set_checkbox` falls under the `field_writes` confirmation point, the other actions under `all_writes`. The tool count is 61.
- **`sap_select_alv_columns`: select columns of an ALV grid by name** ([#53](https://github.com/kts982/mcp-sap-gui/pull/53)). The grid's Total, Subtotals, Sort and Filter functions act on the selected columns, and no tool could select one. Comma-separated names, `""` clears, `add=true` keeps what is selected. A name the grid does not have selects nothing.
- **A SAP session that opens beside the agent's is reported** ([#52](https://github.com/kts982/mcp-sap-gui/pull/52)). A hotspot, a "Navigate to..." function or a menu entry can show a document in a session of its own; the session the agent is in then looks unchanged, and the response read as if nothing had happened. Only `/o` in `sap_execute_transaction` was noticed. Now the `screen` of a response lists a session that appeared on the connection under `new_sessions` (`session_id`, `transaction`, `title`), once, with a note. The agent stays in the session it was in, and the report gives no index to attach with: it cannot tell whether an action or the user opened the session, so the note says to tell the user. The session shows after the action has returned: 0.5 to 0.7 seconds later on a local system, 3 to 5 seconds on a remote EWM system (a document hotspot in `/SCWM/MON`). No action waits for it, so it is reported with the first response that carries `screen` once it is there: when an action that should have opened a document seems to have done nothing, `sap_get_screen_info` says whether a session opened.

- **An ALV read marks the totals lines of the layout** ([#51](https://github.com/kts982/mcp-sap-gui/pull/51)). A total or subtotal counts as a row but is a sum, not a record: a grid with a total and two subtotal levels showed 40 rows for 30 records, and a subtotal row carries its group's key values, so it read like a record with empty fields. When the grid's layout has totals lines, `sap_read_table` now reports `totals_lines` (`highest_level`, `above_entries`) and marks each total or subtotal row among the rows read with `_total_level`: 1 is the innermost subtotal, the highest the overall total (the counter row of `/SCWM/MON` is level 1). A subtotal whose group is closed carries `_collapsed`, with a `warning`: its records are not in the grid. `total_rows` still counts every row. A grid without totals lines reads as before; the check is two calls, under 2 ms.

- **`sap_screenshot` can mark and mask fields and add a caption** ([#55](https://github.com/kts982/mcp-sap-gui/pull/55)). With `save_path`: `highlight=[targets]` frames them in red, `mask=[targets]` blacks out protected data, and `caption="..."` adds a strip under the image. A target is an element ID, or for an ALV grid `{"id": "<grid id>", "column": "MATNR", "row": 3}` (one visible cell; `row` left out, the visible part of the column). `isolate=true` blacks out everything outside the highlighted areas. `include_context=true` adds system, client, user, transaction and time to the caption; it needs a caption and is off by default because it exposes the user ID. A target needs a size and must lie inside its container (the user area, the grid) and the captured window (the popup, when one is open); a cell partly scrolled out of view is masked where it shows and refused for `highlight` and `isolate`; the targets are read again after the capture, and the call is refused if they moved or if the image is not the size SAP reports for the window. A maximized window on plain SAP GUI is the one accepted difference: SAP reports it with its invisible frame, and the image comes without it. Nothing is saved in those cases, and the file is written only after masking. `mask` blacks out the named elements only: the same value in the title or the status bar stays.

### Fixed

- **`sap_get_screen_elements` says when `max_depth` cut the scan short** ([#61](https://github.com/kts982/mcp-sap-gui/pull/61)). A tree 16 levels below `wnd[0]` came back as `element_count: 0` at `max_depth` 14, with or without `type_filter`, and nothing said why (seen live on a case display: the tree was found from 16 on, by the same filters). The response now carries `depth_limited` (`containers_cut_off`, up to three `examples`, and a `note` when the result is empty) when the scan stopped inside containers that still had children, also when the result is empty; it is absent when the whole container was read. Menus are not counted or given as examples unless the scan started in the menu bar. A table control kept as one element is not counted. The tool description says to raise `max_depth` or pass an example as `container_id`.

- **The tree and grid guides find a tree that sits deep** ([#64](https://github.com/kts982/mcp-sap-gui/pull/64), [issue #62](https://github.com/kts982/mcp-sap-gui/issues/62)). The SPRO and Warehouse Monitor guides looked for the tree, and the Warehouse Monitor guide for the result grid, from the user area down to depth 6; a real tree was seen 16 levels down, and the scan came back empty. They now scan from `wnd[0]` with `max_depth=30`, a scan that takes longer (0.1 to 0.4 s instead of under 60 ms in Business Client 8.10, one machine) and that a filter keeps small. The `sap_get_screen_elements` description no longer says these elements usually sit 3 to 6 levels deep.

- **A transaction code with `-`, `.` or another special character is checked like any other** ([#57](https://github.com/kts982/mcp-sap-gui/pull/57), [issue #56](https://github.com/kts982/mcp-sap-gui/issues/56)). SAP's own codes use most of the keyboard (`F-02`, `F.13`, `BRF+`, `FF$3`, `MC=1`), and the transaction policy knew only letters, digits, `_` and `/`. Typed into the command field without a prefix, such a code was taken for a function code and not checked at all, also with `--policy-preset strict`; on the SAP Easy Access screen that starts the transaction. `sap_execute_transaction` refused the same codes as invalid, and a policy file could not name them. A code now starts with a letter, a digit or `_` and goes on with any visible character except `*`, `/` and `;`. It is checked in the command field with and without a prefix, `sap_execute_transaction` starts it, and `block` and `allow` take entries like `F-02` and `F-*`. A value that starts with another character (`%PC`, `&ALL`) stays a function code. With `strict`, a function code such as `P+` typed into the command field needs an `allow` entry now, as `BACK` did before. A policy entry with `]` is refused at startup: a set of characters like `[AB]` was never supported and would match nothing.

- **`sap_screenshot`: an ALV cell highlight or mask hit the wrong place when the display scaling is not the one SAP GUI started with** ([#59](https://github.com/kts982/mcp-sap-gui/pull/59)). The grid reports cell offsets and sizes in the system DPI of its own process, which Windows fixes when the process starts. On one setup the grid's own position stayed in physical pixels, so after a monitor change the box came out too small, too high and too far left, with no error. The offsets are now scaled by the effective DPI of the window's monitor over the process's system DPI, so a process that started at the window's scaling is left as it was. On other setups the window is reported in the process's units as well, every length larger or smaller than the image by one factor: the highlight or mask is now drawn there (the factor is the image size over the reported window size, and each edge is rounded outward so that a mask never ends inside what it hides) where it was refused. It is still refused when width and height disagree, as for a maximized plain SAP GUI window, and when Windows gives no DPI. Seen live on SAP GUI 8.10 PL1 and PL2, in Business Client and plain SAP GUI: system DPI 96 with a window at 144 gives cells of 17 px for a row that is 26 px on screen, and Business Client started at 100% on a display then set to 175% reports a window of 3199x1778 as 1828x1016. Starting SAP GUI again at the current scaling makes every value physical.
- **`sap_press_column_header` said it sorts** ([#53](https://github.com/kts982/mcp-sap-gui/pull/53)). It sends a click on the column header to the application, which on a standard grid neither selects the column nor sorts by it (checked live: no selected column, no sort, rows unchanged). The description now says so and points to `sap_select_alv_columns` and the grid's own functions.
- **A screenshot no longer shows another application or another session in Business Client** ([#54](https://github.com/kts982/mcp-sap-gui/pull/54)). There `HardCopy` copies the window's rectangle from the screen, so a window on top, or another tab, ended up in the image, and a minimized window gave a black one that was reported as a success. In Business Client the window is now rendered by its handle (`PrintWindow`, at the display's real resolution; the result says `capture: printwindow`). A minimized window or a hidden tab is refused with a message, and without Pillow the call fails and names the `screenshots` extra instead of copying the screen. Plain SAP GUI keeps `HardCopy` (`capture: hardcopy`), which draws the window itself, and now refuses a minimized window.

## 0.6.1 — 2026-11-16

F11 and the Save button are sent only if the screen, system, client, user and SAP session still match the question. Responses add the screen's `buttons` and, for an ALV grid, its title and selection; `sap_read_table` names the columns, rows and cells it could not read; tree double-clicks are sent as the event the tree registered (SE19, SM34 view clusters, `/SCWM/MON`). `opentelemetry-api` 1.45.2 fixes CVE-2026-126360.

### Added

- **The screen info names the buttons on the screen** ([#41](https://github.com/kts982/mcp-sap-gui/pull/41)). Every action response now carries `buttons`, the pushbuttons with a text in the main window's user area as `{ID: text}`. EWM RF menu pages share one sub-screen and one cursor field, so before this each page looked the same and needed an element list; and an RF F-key button changes its meaning ("F1 Logoff" on a menu, "F1 Save" on the logoff screen). Only the buttons' texts are read, about 1.5 ms each; a screen without buttons costs nothing. Icon-only buttons and popups (their digest lists the buttons) are left out, and so is a screen with more than 15 buttons.
- **An ALV read names the grid and what is selected** ([#40](https://github.com/kts982/mcp-sap-gui/pull/40)). `sap_read_table` on an ALV grid adds, when set, the grid's `title` and its selection: `selected_rows` in SAP's own form (`"1,2,4-8,10"`) with `selected_row_count`, `selected_cells` and `selected_columns`. Toolbar and menu functions, such as the "More Methods" of `/SCWM/MON`, act on the selected rows; the tools could set that selection but not read it. The title tells two grids on one screen apart.

### Fixed

- **A save goes only to the screen it was approved for** ([#42](https://github.com/kts982/mcp-sap-gui/pull/42)). The Save button in the toolbar (`wnd[0]/tbar[0]/btn[11]`) was pressed on whatever screen was current when the answer came, and F11 was checked again only on MCP 2026-07-28. Both now read the screen, system, client, user and SAP session for the question and again just before the save. If anything changed while the question was open (you moved on in SAP GUI, a popup opened), nothing is sent: the result is `status: cancelled`, `action: changed`, and lists what changed. The question names the screen and system the save goes to. A declined Save button is now reported like a declined F11 (`status: cancelled` with an error) instead of as a tool error. On MCP 2026-07-28, an answer that arrives after the screen changed no longer reads "declined by user". With `all_writes` on, the question for any button no longer says "press the SAP Save button".
- **The documentation promised more than the save check covers** ([#42](https://github.com/kts982/mcp-sap-gui/pull/42)). "Saving always waits for your yes" now reads "a save with F11 or the Save button". [Confirmations](docs/CONFIRMATIONS.md#known-gaps) says the server recognises a save by how it is sent, not by what it does in SAP: an application function that posts, or a function code typed into the command field, does not ask unless `all_writes` is on.
- **A table read says what it could not read** ([#43](https://github.com/kts982/mcp-sap-gui/pull/43)). `sap_read_table` with column names the table does not have dropped them without a word, and a read with only such names returned rows that held nothing but their index. Now no known name is an error that lists the table's column names (`unknown_columns`, `available_columns`), and some unknown names are listed in `unknown_columns` while the rest is read. A table-control row whose cells all failed to read no longer ends the data when rows below it have data: it comes back with null values, listed in `unreadable_rows`. An ALV cell that could not be read is listed in `unreadable_cells`; an empty cell still reads `""`. The table export guide also says that an ALV grid can end with a totals row, such as the counter row of `/SCWM/MON`.
- **`type_filter` finds trees and grids by their class** ([#44](https://github.com/kts982/mcp-sap-gui/pull/44)). A tree, an ALV grid or a text editor reports the type `GuiShell`, so `type_filter="GuiTree"`, the call in the SPRO and Warehouse Monitor guides, found nothing, and an agent following the guide could conclude there was no tree. `sap_get_screen_elements` now reports a shell's `subtype` (`Tree`, `GridView`, `TextEdit`, ...), and `type_filter` finds it by its class (`GuiTree`, `GuiGridView`, ...), its bare subtype, or every shell by `GuiShell`, in any case. The guides pass `max_depth=6`, deep enough to reach these controls.
- **Code mode: the audit log no longer keeps a script's text** ([#45](https://github.com/kts982/mcp-sap-gui/pull/45)). With `--code-mode` the `execute` line logged the whole script, and masking by name cannot find a password written into source code: it was masked on the nested call's line and in clear on the `execute` line. The script is now recorded by its hash and size (`sha256`, `chars`, `lines`); each call it makes is still logged on its own line, masked.
- **Column titles and tooltips come without their padding** ([#46](https://github.com/kts982/mcp-sap-gui/pull/46)). SAP GUI pads them to the field length: on an SE16 grid the tooltip "CARRID" came with 114 spaces. `sap_read_table` and `sap_get_column_info` now strip them.
- **The profiles table said `full` shows more than `operator`** ([#46](https://github.com/kts982/mcp-sap-gui/pull/46)). No tool carries the `destructive` tag, so both show the same tools today; [Configuration](docs/CONFIGURATION.md#profiles) now says so.
- **Tree double-clicks reach the application as a mouse double-click does** ([#39](https://github.com/kts982/mcp-sap-gui/pull/39)). In SE19's BAdI implementation editor the tree could not be driven: `sap_double_click_tree_item` reported `double_clicked` and nothing opened, because SE19 opens the selected node, not the one the event names. A double-click now selects the node first. It is also sent the way the tree registered it (`GuiShell.OcxEvents`): in an SM34 view cluster, which reacts only to item double-clicks, `sap_double_click_tree_node` now switches the view (`sent_as: item_double_click`), and in `/SCWM/MON`, which reacts only to node double-clicks, `sap_double_click_tree_item` now opens the node. A tree that reacts to no double-click still gets the click, with a `warning` that names what it does react to. `sap_read_tree` and the root listing of `sap_get_tree_node_children` list the tree's `events`.
- **A tree that renumbers its nodes no longer ends in a bare COM error** ([#39](https://github.com/kts982/mcp-sap-gui/pull/39)). SE19's tree numbers its nodes anew after every round trip, so the next call with an old key failed with "Exception occurred". The error now says the key is no longer in the tree and to read the tree again, and a double-click or link click that renumbered the tree returns `node_keys_changed: true`.
- **The SPRO guidance said a double-click opens an activity's documentation.** It does nothing there; link column `"1"` opens the documentation, column `"2"` runs the activity. Corrected in the server instructions, the SPRO guide and the tool descriptions.

### Dependencies

- `opentelemetry-api` 1.45.1 → 1.45.2 (through fastmcp and the MCP SDK) for [GHSA-mf5v-w3w3-f6cg](https://github.com/advisories/GHSA-mf5v-w3w3-f6cg) (CVE-2026-126360) ([#48](https://github.com/kts982/mcp-sap-gui/pull/48)): a crafted `traceparent` value in a request's `_meta` could cost the server a lot of CPU time and hold up the other requests meanwhile. The MCP SDK reads that value on every request, so the server was affected: a 16,000-character value took 0.6 s, and the time grows with the square of the length. 1.45.2 refuses a value longer than 512 characters. Availability only.
- `dnspython` 2.9.0 → 2.9.2 (through pydantic's `email` extra, which fastmcp uses) for [GHSA-vvf4-9x63-8xvv](https://github.com/advisories/GHSA-vvf4-9x63-8xvv) (CVE-2026-128089) ([#48](https://github.com/kts982/mcp-sap-gui/pull/48)): a crafted WKS record in zone-file text could use up memory and CPU time. The server reads no zone files and does not load dnspython.

## 0.6.0 — 2026-10-28

Support for MCP 2026-07-28 next to the earlier protocol versions, with confirmation questions that hold on both; Python 3.11 or later; documentation reorganised by task.

### Added

- **MCP 2026-07-28.** The server runs on FastMCP 4 and serves the newest MCP protocol version next to the earlier ones: each client gets the version it asks for. The confirmation questions work on both. On 2026-07-28 a question is a round of its own: the tool runs again when the answer arrives, and the answer counts only if what the question showed (the screen for a save, the popup and its button, the list of sessions, the points to remove) is still the same; otherwise nothing is done and the agent is told to look again. An answer counts once, and an answer faster than a person (under 250 ms) is refused as before. Tested on 2026-10-28 with the Claude Code CLI, the GitHub Copilot CLI, VS Code with GitHub Copilot and the Codex CLI: [Clients](docs/CLIENTS.md). Over HTTP a 2026-07-28 request is refused, because it carries no client identity and the server could not keep one SAP session per client; stdio works with every version.
- **The audit log names the MCP client and protocol.** Every `tool_call` line carries `protocol` (the MCP protocol version of the request, for example `2026-07-28`) and `mcp_client` (the client's name and version as the client reports them, for example `claude-code 2.1.312`). A question to the user on MCP 2026-07-28 is a round of its own: the call returns `status: input_required`, and the call with the answer is a second line.

### Removed

- **`sap_set_policy_profile`**, 59 tools now. It switched a chat to a smaller set of tools by hiding the others for that session. MCP 2026-07-28 does not allow a tool list that varies per client, and FastMCP 4 keeps such hiding per server process on that protocol, so one chat's choice would hide tools for every chat. The server-level `--profile` stays and applies to every chat; to be asked before writes in one chat, use confirmation points (`sap_set_confirmation_points`). 0.5.4 kept the tool and made its restriction hold ([#37](https://github.com/kts982/mcp-sap-gui/pull/37)).

### Changed

- **The documentation is reorganised by task.** The README is a short front page, and its links now work on the PyPI project page too (they were broken there). New pages: [Getting started](docs/GETTING_STARTED.md), [Confirmations](docs/CONFIRMATIONS.md), [Configuration](docs/CONFIGURATION.md) (every option and environment variable in one place), [Security guide](docs/SECURITY_GUIDE.md) (with a reference of the audit log fields), [Preparing SAP](docs/SAP_SETUP.md) and [Troubleshooting](docs/TROUBLESHOOTING.md); [Clients](docs/CLIENTS.md) starts with which clients show the confirmation questions. Corrected on the way: Claude Code's user-wide setup is `claude mcp add --scope user` (there is no `~/.claude/.mcp.json`); the SPRO advice no longer suggests reading the whole SPRO tree; and the `SAP_*` logon variables are read from a `.env` file only in a source checkout, so with `uvx` they go into the client's `env` setting.

### Fixed

- **After a declined question, an agent could refuse the user's next instruction too.** The server's rules said a declined confirmation "is a stop"; GitHub Copilot in VS Code read that as final and would not run a step the user asked for afterwards. The rule now says what it meant: do not retry the call or reach its result another way, tell the user, and wait for their next instruction.
- **A no given in VS Code read as "(accept)".** VS Code answers a yes/no question with True or False and Submit, so a no arrived as a submitted form with the box not ticked, and the refusal said "declined by user (accept)". It now says `(no)`, and the result's `action` is `no`.
- **The question for a popup answer is labelled with its button.** It was labelled "Yes, save" for every answer, also for No on a "Data may be lost." popup; it now reads `Yes, press 'No'`. F11 keeps "Yes, save".
- **The refusal on a client that cannot show the question says what to do.** It ended in "the client does not support elicitation: Method not found". In the Claude desktop app's Chat and Cowork tabs the agent then guessed which clients would work, or offered to turn the confirmation point off, which needs the same question. The refusal now says that nothing was run, that the point cannot be turned off from that client either, and to tell the user and use a client that shows MCP confirmation dialogs.
- **An HTTP client that went away left its SAP binding behind.** Its binding, its confirmation points and any SAP session the server had opened for it stayed until the server stopped. When an HTTP session ends now, because the client closes it or it expires after 30 idle minutes, the server releases the binding, drops the points, and closes the SAP sessions it opened for that client (left open with `--detach-on-exit`). stdio is unchanged.

### Python versions

- **Python 3.11 or later is required.** Python 3.10 reached end of life on 2026-10-01, and 0.5.x was the last line that supported it. The `screenshots` extra now installs Pillow 13 on every supported Python, and every Python gets the fixed dnspython, so the dependency audit no longer skips GHSA-45c3-73f7-pv4m.

## 0.5.4 — 2026-10-27

A security release for the HTTP transport, a session profile that holds, and the server's own version in `serverInfo`. stdio, the default transport, was not affected by the security issue.

### Safety

- **The HTTP transport refuses requests a web page could forge** ([GHSA-rqrh-r823-7mqf](https://github.com/kts982/mcp-sap-gui/security/advisories/GHSA-rqrh-r823-7mqf)). With `--transport http`, any `Host` and `Origin` header was accepted, so a page opened in a browser could point its own domain at 127.0.0.1 (DNS rebinding), act as an MCP client and use the bound SAP session, answering the confirmation prompts itself. A request addressed to another host name now gets 421, and a browser request from another origin 403. `--allowed-host` and `--allowed-origin` add names and origins, for example with `--host 0.0.0.0`; such a bind without `--allowed-host` logs a warning. MCP clients send no `Origin` and are not affected. stdio, the default, has no network surface.
- **A session profile no longer lapses after a day** ([#37](https://github.com/kts982/mcp-sap-gui/pull/37)). `sap_set_policy_profile` hid tools through FastMCP's session state, which expires 24 hours after it was set: the hidden write tools were then listed and callable again, without notice. The server now keeps the profile itself and refuses a tool outside it on every call, also from a `--code-mode` script. The `--profile` floor and the confirmation points were not affected.

### Fixed

- **The server reported FastMCP's version as its own** ([#36](https://github.com/kts982/mcp-sap-gui/pull/36)). The `initialize` answer named the server `mcp-sap-gui` but carried the installed FastMCP's version (0.5.3 reported `3.4.11`). It now reports the package version.

## 0.5.3 — 2026-10-27

Session commands refused, only the server's own SAP sessions closed, and a choice of the session to attach to. Six of these changes were contributed by [@nelz0n](https://github.com/nelz0n); the session changes were checked live on SAP GUI 8.10 and 8.00.

### Safety

- **The audit log no longer writes a password typed into a field.** `sap_set_field` on a password field (e.g. `pwdRSYST-BCODE`) logged the value in clear text; only `sap_set_batch_fields` masked it. Now, when an argument names a secret-looking target (a field ID, a table column, a text editor), the value written into it is logged as `***`. The target stays visible, so the audit still shows which field was written.
- **Session commands are blocked, and three ways around the transaction policy are closed** ([#25](https://github.com/kts982/mcp-sap-gui/pull/25), by [@nelz0n](https://github.com/nelz0n)).
  - `/nex` (log off, closing every session of the connection without asking), `/nend` and `/i` (close a session; `/i3` closes session 3) passed the `default` and `abap-dev` presets, through `sap_execute_transaction` and through the command field. They are now refused with their own message; a policy file can still allow one (`"allow": ["EX"]`).
  - `sap_set_textedit` on the command field skipped the transaction check, so `/nSU01` got through. It is now checked like `sap_set_field`.
  - A command-field value that starts a transaction but does not parse as a whole (`/*SU01 USR02-BNAME=X`, which skips the first screen with a field filled) was not checked at all. The code it names is now checked, and one the policy cannot check is refused.
- **The server closes only the SAP sessions it opened** ([#26](https://github.com/kts982/mcp-sap-gui/pull/26), by [@nelz0n](https://github.com/nelz0n)).
  - After `sap_connect`, an `/o` command moved the binding to `GuiApplication.ActiveSession` (which can be a window the user works in, on any connection) or to the last session of the connection (which can be an existing one), and `sap_disconnect` or server shutdown then closed that session, while the one the server had opened stayed open. The server now keeps the sessions it opened, the `sap_connect` logon session and `/o` windows opened from it, and closes only those, newest first; one the user already closed is skipped.
  - `/o` binds only a session that was not on the bound connection before the command (it waits up to 2 seconds for it) and reports `new_session_bound`. An `/o` window opened from an attached session is attached too, so it is never closed.
  - `--detach-on-exit` leaves every session open on shutdown, including the ones the server opened.
  - `sap_connect` is no longer annotated read-only, and `sap_disconnect` is annotated destructive. Both keep the `read` tag, so every profile can still log on and detach.

### Added

- **Choose the SAP session to attach to.** `sap_connect_existing` takes `system` (`DEV`, or `DEV/100` with the client) for when the user named the system: one open session on it is attached, and several or none return an error that lists what is open. A new opt-in confirmation point `attach` (`--confirm attach`, or `sap_set_confirmation_points`) lets the user pick the session in a dialog, unless the call names a system with exactly one open session; a client without dialogs gets an error telling the agent to ask in the chat. `sap_list_connections` adds each session's `session_number` and window `title`, the response says how the session was chosen (`chosen_by`), and the audit log records an `attach` event. After the dialog or the name lookup, the server checks that the session it attached is the one chosen (sessions can open or close meanwhile) and attaches nothing if not; attaching and the check are one step, so no other tool call reaches the session before it is checked. Without the point and without `system`, attaching works as before.
- **The audit log names the SAP system of each call.** Every `tool_call` line carries `sap: {"system", "client", "user"}` of the session the chat is bound to, so a log that spans several systems can be split by system. An attach names the system it attached, a disconnect the one it left; while nothing is bound the key is left out. The values are read when a session is attached or opened, and `sap_get_session_info` refreshes them (a `sap_connect` window has no user until the logon).
- **Which radio button or checkbox is selected.** `sap_read_field`, `sap_get_popup_window` (`interactive_elements`) and `sap_get_screen_elements` report `selected` for radio buttons and checkboxes. It is read over COM for each of them, never through GetObjectTree, which crashes SAP GUI 8.00 when asked for it. A changeable radio button or checkbox that is selected in a popup is listed in `prefilled_inputs` with the notice, like a pre-filled field: a popup can open with an option already chosen (SCAL's holiday dialog: "with fixed date").
- **`--strict-errors`** ([#28](https://github.com/kts982/mcp-sap-gui/pull/28), by [@nelz0n](https://github.com/nelz0n)). Most SAP failures come back as a normal result with an `error` key, so a client that checks only `isError` treats a refused write as done. With `--strict-errors` (or `MCP_SAP_GUI_STRICT_ERRORS=1`) such a result, and a `sap_set_batch_fields` call with a field that was not set, is returned with `isError: true` and its structured content unchanged. Off by default. Inside a `--code-mode` script `call_tool` still returns the result, so scripts check `error` themselves.
- **Read results say when they are incomplete** ([#29](https://github.com/kts982/mcp-sap-gui/pull/29), by [@nelz0n](https://github.com/nelz0n)). A table-control read adds `next_start_row` and `has_more`, echoes `start_row`, and adds a `start_row_note` when the table could not be scrolled to the requested row. `sap_read_tree` adds `available_nodes` and `truncated`, `sap_search_tree_nodes` adds `searched_nodes` and `stopped_early`, and `sap_read_table`, `sap_read_tree` and `sap_search_tree_nodes` add `capped_to` when the server lowered the limit you asked for.

### Changed

- **`sap_set_field` refuses a value that does not fit before writing** ([#28](https://github.com/kts982/mcp-sap-gui/pull/28)). A value longer than the field (`MaxLength`) or a field that is not changeable gives `status: "rejected"` with the reason, and `max_length` / `value_length` for a value that is too long; the field keeps its content. Before, both came back as "Could not set field". `sap_set_batch_fields` explains a refused field the same way.
- **The audit log marks failed results as errors** ([#28](https://github.com/kts982/mcp-sap-gui/pull/28)). A result with an `error` key, or a batch with a field that was not set, is logged with `status: "error"` and an `error_msg`, at WARNING, in every mode. Before, only an exception was. Counts of errors in existing audit logs go up.
- **A declined save or popup answer carries `error`** ([#28](https://github.com/kts982/mcp-sap-gui/pull/28)): "Save declined by user (…). Nothing was sent." / "Popup answer declined by user (…). Nothing was pressed.", next to the unchanged `status: "cancelled"`.
- **An answer that no person gave is treated as one.** The Claude Code desktop app (tested 2026-10-19) answers every confirmation prompt with "decline" within milliseconds and shows nothing; the Claude Code CLI shows them. An answer faster than a person can give one (under 250 ms) came from the client: a "no" still counts, and the error adds that no dialog was shown and the request cannot be approved in that client; a "yes" is refused, because no person approved it, so a client or hook that answers for you cannot approve a save. Every `confirmation` audit line now has `elapsed_ms`, `no_dialog: true` for such an answer, and `client_answer: "accept"` for a refused yes. All prompts go through one helper with these rules.
- **`sap_set_batch_fields(validate=true)` no longer presses Enter when a field failed** ([#29](https://github.com/kts982/mcp-sap-gui/pull/29)): Enter on a half-filled screen checks only what was set. `validation` then says `performed: false` with the reason. `validate_partial=true` keeps the old behaviour.
- **`sap_get_popup_window` says where a popup's text is** ([#30](https://github.com/kts982/mcp-sap-gui/pull/30), by [@nelz0n](https://github.com/nelz0n)). Labels and display-only fields are in `texts`; the body of a classic list (an F4 hit list, a SAP note, a message long text) is in `list`, and its lines are never in `texts`. Every list popup now gets the same hint: read the lines with `sap_read_list(window_id=...)`, and in an F4 hit list pick a line by its ID, then Enter. The docstrings and [TOOLS.md](docs/TOOLS.md) say the same.

### Fixed

- **Table-control paging skipped rows** ([#29](https://github.com/kts982/mcp-sap-gui/pull/29)). One read returns at most the visible rows, but the guidance stepped `start_row` by `max_rows`, so every row between the visible ones and the next step was missed. Page with `start_row=next_start_row` while `has_more` is true. Checked live: an SM30 view with 137 entries reads every entry once.
- **A blank New Entries line with a dropdown read as an entry** ([#29](https://github.com/kts982/mcp-sap-gui/pull/29)). The dropdown's empty entry reads as a single space; a whitespace-only cell now counts as blank, so `empty_rows_from` marks where the data ends.
- **`validation.performed` was true when Enter was refused or failed** ([#29](https://github.com/kts982/mcp-sap-gui/pull/29)). It is now false, with the error.
- **One "allow scripting" dialog per SAP GUI process, not one per tool call** ([#32](https://github.com/kts982/mcp-sap-gui/pull/32), by [@nelz0n](https://github.com/nelz0n)). Since 0.5.0 every `sap_list_connections` and `sap_connect_existing` looked up the scripting engine of each SAP GUI process again, and a system with `sapgui/user_scripting_force_notification` set asks the user at each lookup, for each of its connections. The engine of each process is now kept and reused while it answers; one that stops answering (SAP Logon restarted) is looked up again, and a GUI server process that ended is forgotten.
- **`sap_connect` failed after SAP Logon was restarted, until the server restarted.** It kept the SAP Logon engine from its first use; after a restart that engine was dead and `OpenConnection` failed. It now uses the engine discovery keeps, checked before each use, so a new SAP Logon is picked up.

They are all in decoding or encoding image files; the server opens only the PNG that SAP GUI writes for a screenshot. Pillow 13 needs Python 3.11 and there is no 12.x fix, so on Python 3.10 the `screenshots` extra now installs nothing: `sap_screenshot` still works, but the image is no longer downscaled or optimized.

## 0.5.2 — 2026-10-18

Popup answers that ask first, and table writes on the right row. Three of these fixes were contributed by [@nelz0n](https://github.com/nelz0n); all were checked live on SAP GUI 8.10 and 8.00.

### Safety

- **A popup answer that may save asks first, as F11 does** ([#27](https://github.com/kts982/mcp-sap-gui/pull/27)). This covers `sap_handle_popup` (`confirm`, `press`) and `sap_press_button` on a popup button by ID. A popup is save-shaped when the button saves, or when its text is about saving and it offers more than one answer.
- **Popup questions the server cannot read.** SAP's confirmation popup (SAPLSPO1, e.g. "Save before exiting editor?", "Data may be lost") draws its question in an HTML viewer. With the Internet Explorer browser control the question is read into `texts`. With Edge (the default) scripting cannot read it: the popup reports `question_readable: false` with a `question_note`, is classified `confirmation`, and any answer but Cancel asks the user first.
- **`cancel` never presses No.** It presses a Cancel-type button (in the common logon languages) or F12. On a save prompt, No left the editor and dropped the changes.
- **`sap_send_key` checks the key before asking to save.** F11 / Save on a screen where it is not active is refused with the available keys, without a save prompt first.
- **Table-control writes after a scroll land on the right row.** Setting `VerticalScrollbar.Position` can put a different row on top than the one asked for (SE16's multiple selection: row 7 or 8 for 9, 14 for 15). `sap_modify_cell`, `sap_set_current_cell` and `sap_double_click_cell` counted visible rows from the requested position, so a write could go into another row and still report success. They now count from the row SAP put on top, and refuse with "Nothing was changed" when the row is still not visible. Row selection was not affected.

### Fixed

- **Element IDs with any SAP screen name** ([#24](https://github.com/kts982/mcp-sap-gui/pull/24)). Unnamed elements (`%#AUTOTEXT001`), `*` work areas (SE24), `=>` and `->` attributes (SLIN), field symbols `<FS>` and `+ & ' ! ? " ( ) {` were refused by the tools that take an element ID. A path segment is now a type prefix plus anything but whitespace and `/ [ ]`; the `wnd[n]` prefix and the top-level children are still checked.
- **A closed SAP window fails at once** ([#31](https://github.com/kts982/mcp-sap-gui/pull/31)). `RPC_E_DISCONNECTED` (0x80010108) and `RPC_S_SERVER_UNAVAILABLE` (0x800706BA) raise a "reconnect with `sap_connect_existing`" error at once, instead of three retries (about 2 s) and the raw COM error. `RPC_E_SERVERFAULT` (0x80010105) is SAP GUI's stale-reference error and is no longer retried: the retry re-ran the whole tool body, presses and keys included. Only `RPC_E_CALL_REJECTED` and `RPC_E_SERVERCALL_RETRYLATER` are retried, and the HRESULT names in the code are now right.
- **`sap_scroll_table_control` reports the row actually on top.** `position` is the row SAP put at the top; `requested_position` and a `note` are added when it differs from the one asked for.
- **`sap_read_table` with `start_row=0` on a table control starts at the first row.** It read from wherever the table was scrolled. Without `start_row` the read still starts at the current scroll position, e.g. after "Position...".
- **ALV toolbar: a plain button is pressed, not opened as a menu.** On SAP GUI 8.10 `PressToolbarContextButton` on a plain button runs it instead of failing, so Find opened its popup and was reported as `menu_opened`. The button's type on the toolbar now picks the press.
- **`sap_handle_popup`:** when the Enter or F12 fallback leaves the popup as it was, the result is `action: "no_effect"` instead of `confirmed`.

### Dependencies

- `mcp` 1.28.1 → 1.30.0 (through fastmcp) for [GHSA-84m7-p3x7-pcfv](https://github.com/advisories/GHSA-84m7-p3x7-pcfv) (CVE-2026-59951): the Streamable HTTP transport kept every session, so a client could exhaust the server's memory. This affects `--transport http` only. With 1.30.0, an HTTP session idle for 30 minutes is closed (a client that does not keep the event stream open then has to initialize a new session, which starts without the old session's SAP binding), and a server holds at most 10,000 sessions. stdio is unchanged.

### Release

- `SHA256SUMS.txt` no longer lists `dist/.gitignore`, which was never a release asset.

## 0.5.1 — 2026-10-15

A crash fix for SAP GUI 8.00, and screens that say more.

- **No more SAP Logon crashes on SAP GUI 8.00.** On 8.00, reading a table control or a classic list in one call could take SAP Logon down with every session in it ([issue #22](https://github.com/kts982/mcp-sap-gui/issues/22)). The cause was one property in that call: the server no longer asks for it and reads checkboxes one by one, still about 3x faster than reading cell by cell. Two environment variables, contributed by [@nelz0n](https://github.com/nelz0n) in [#23](https://github.com/kts982/mcp-sap-gui/pull/23), turn the one-call read off per call site and trace each call to a file, for any other SAP GUI build that misbehaves. Which SAP GUI releases SAP still supports, and what needs which: [SAP GUI Versions](docs/SAP_GUI_VERSIONS.md).
- **Screen info names sub-screens and the cursor.** Every action response lists the active window's sub-screens (`subscreens`, as `program:dynnr`) and the field the cursor is in (`cursor`), so an RF step, a tab page or a redisplay that only moves the cursor shows without a screenshot.
- **Table controls say where their data ends.** `sap_read_table` on a table control reports `empty_rows_from`, the first padding line: `total_rows` also counts the empty lines that pad an SM30 view.
- **Confirmed writes say so.** After you approve a save or another confirmation point, the result carries `confirmed_by_user: true`, so the agent can tell an approved write from an ungated one.

## 0.5.0 — 2026-10-06

The SAP GUI Scripting API, used to the full. This round went through the 8.10 Scripting API guide on a trial system and closed the gaps it found:

- **Much faster on large screens.** On SAP GUI 7.70 PL3 or later a whole screen, popup, list page or table control is read in one call (`GetObjectTree`): a 1,139-cell list page takes 0.2 s instead of 4.7 s. Older releases fall back to reading element by element.
- **Value help that agents get right.** F4 popups are recognised for what they are (hit list, restriction dialog, date picker, time picker) and never auto-cancelled, and a rewritten `search_help` guide covers each case. Dropdowns are set with `sap_set_field` and `sap_set_batch_fields` by key or text, and discovery shows their selected key instead of 200 padded characters.
- **Safer popups.** SAP's message popups are recognised in any logon language, and only an information message is ever auto-confirmed: a warning standing between you and a save is always left to you.
- **Keys that mean what they say.** `sap_send_key` refuses a key the screen does not accept and lists the ones it does, and `Ctrl+F` / `Ctrl+G` / `Ctrl+P` now send Find / Find next / Print (they sent Ctrl+F8 to Ctrl+F10 before).
- **More of SAP's own metadata.** Session info reports the SAP GUI release and whether the server only allows read-only scripting (write tools then refuse up front); ALV cells report their type, error or warning state, F4 help and hotspots; an ALV toolbar menu lists its items when it opens; a status message with a long text says so, and pressing the status bar opens it.
- **SAP Business Client (experimental).** Sessions of Business Client's embedded SAP GUI are discovered next to SAP Logon's. Details: [SAP Business Client](docs/SAP_SETUP.md#sap-business-client-experimental).

Changed behaviour when upgrading: discovery elements no longer carry `visible` (SAP GUI Scripting has no such property, so it was always true); F4 hit lists are classified `list` instead of `information`; a key the screen does not accept returns an error with `available_keys` instead of a COM error.

## 0.4.0 — 2026-09-20

Shaped by two days of real agent work on a live system. The lesson was that token cost per call hurts more than missing tools, and that a few screens could not be reached at all:

- **Lighter responses.** A table control is one discovery element instead of one per cell (an SM30 screen went from 231 elements to 3), element IDs come back in the short `wnd[0]/...` form, and batch fills and popup actions report what matters instead of echoing everything.
- **`sap_read_list`** reads a classic report list (`WRITE` output, F4 hit lists) as lines of text with list colours and paging — 43 lines instead of 492 label elements, and no screenshot needed.
- **View clusters work.** Docking containers (`wnd[0]/shellcont`) are valid IDs and discovery points to them, so the dialog structure of SM34 and most IMG activities can be navigated. A new `SM30` transaction guide covers table maintenance and view clusters end to end.
- **Your transaction policy.** Presets (`default`, `abap-dev`, `strict`) plus a policy file with glob patterns replace the hard-coded blocklist. Details: [Transaction policy](docs/SECURITY_GUIDE.md#transaction-policy).
- **Popups announce pre-filled values.** When an action opens a popup, its response already says what the popup is and which inputs hold values you never chose — such as a customizing request pre-filled with another project's request.
- **Screenshots to a file.** `sap_screenshot(save_path=...)` writes a full-resolution PNG for documents and never overwrites a file.
